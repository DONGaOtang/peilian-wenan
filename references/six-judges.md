# 七官出口自检面板（P5 参考文件）

> 视频/平台把烂脚本渲染得和好脚本一样漂亮——出口质检是花钱（拍摄/流量）之前最后一道闸。
> 借鉴 clipforge script-judges 的单轴对抗设计 + 仲裁机制（其原版缺失）+ 终止条件（其原版缺失）+ 逻辑延续检查（借鉴 dbs-script-flow，其原版为独立 skill 未集成）。

## 运行规则

1. 七官全部上场，每官只管一个轴，从自己的角度攻击
2. **一个找到零问题的官是可疑的**——刻薄胜过友善
3. 审出的问题：要么改，要么明确列出「不改的理由 + 不改的后果」（改不止标）
4. **仲裁优先级**（轴冲突时按此排序，前者的判决优先）：

```
事实官（红线，一票否决）> 节奏官（留存）> 逻辑官（断点）
> 契约官（履约）> 口语官（真实感）> IP官（长期一致性）> 结构官（底盘）
```

5. **终止条件**：最多 3 轮「审→改」。第 3 轮后仍有非红线问题 → 列出剩余问题+风险，交用户终审裁决。防死循环，防磨平
6. **校准铁律**：口语官只吃真实创作者的口播转写稿校准，绝不喂获奖广告文案——用精致文案校准的官会把每个稿子都「改进」成广告，这正是本面板要防的。IP官 的校准语料 = P3 对话中用户的原话（最真实）。
**冷启动基准**（无指纹、无转写稿时）：口语官用「写→读→改」三步默认基准——先按常规写，用户朗读后以「念不顺的句子」为第一批评判样本；首条发布后指纹入档，第二条起切换为指纹校准
7. **七官之后是朗读环节**（不可跳过）：用户出声读全稿，标出念不顺/卡壳/气口不对处。七官是 AI 的审，朗读是人的审，两道都过才算毕业

## 七官职责

### 1. 事实官（红线，一票否决）
只管一件事：**有没有编造。**
- 每个数据、案例、经历、引用，必须能追溯到用户在 P3 说过的话或提供的材料
- 用户没说过的：删，或标 [待用户确认] 后当场问
- 发现一处编造 = 全稿冻结，回到素材层（冻结算 1 轮；冻结后补料重写计入 3 轮上限，不额外豁免）

### 2. 节奏官
只管一件事：**句级留存的连续性（微观）。**
- 前 3 秒钩子检查：第一句拦得住拇指吗？（官方数据：流失从第 1-2 秒开始）拦不住 = 死刑，其他优点救不回来
- 每一句必须让观众想听下一句；标记「回答了没人问的问题」的句子
- 长句、绕句、低信息密度的填充词：标记并给出删法
- **不重复结构官的宏观骨架核对**（那是结构官的活：本官只管句与句之间）

### 3. 逻辑官
只管一件事：**段落之间断没断。**（借鉴 dbs-script-flow 三维度，段间+段内两维归此官，句级归口语官）
- **段间衔接**：上一段最后一句和这一段第一句之间有没有逻辑跳跃？观众能不能自然理解为什么要讲这段？缺承上启下就标记，给出过渡句
- **段内密度**：这段有没有重复已说过的信息？有没有绕圈子（5 句话说 1 句话的事）？删掉这段观众会 miss 关键信息吗——不会 miss 且不服务论点 = 可删
- **因果链完整**：每个「所以」前面真的有「因为」吗；动机链断点（为什么突然去做 X？中间缺一步）
- 判断「跑题」前先问：这段在服务哪个论点？答得出服务对象就不算跑题

### 4. 契约官
只管一件事：**承诺的状态迁移兑现了吗。**
- 本条主契约：从 A 到 B。钩子承诺的 B，正文送到了吗？
- 每一段问：这段在推进迁移，还是在原地踏步？
- 只唤起不送达 = 情绪勒索 = 标记违约
- 注意：契约官审的是设计兑现，真实履约由 P6 数据裁定（宪法第四条）

### 5. 口语官
只管一件事：**听着像说的，还是像写的。**
- 「大家好/今天介绍」开场即杀；书面连接词（因此/综上/基于以上）即杀
- 金句结尾、人生道理收尾即杀
- **工整对仗即杀**：「你 X 了，它不知道 Y。你 A 了，它也不知道 B」这种对称句式是 AI 味重灾区——人说话不工整
- 允许少量填充词和半截话（真人指纹），每稿 1-2 次
- **过顺即杀**：全稿零自我打断、零停顿、零改口 = AI 味。真人思维流有「等等」「对，就是这个词」、有话说一半换个说法——**但判据服从说话指纹**：指纹显示用户本来就是流畅型表达者，不强加停顿（强塞「等等」= 伪人味）
- CTA 必须像随口一提（「反正链接我放这了」），不能像口号
- 生造概念/术语未即时解释：观众听不懂的术语 = 划走点，标记（借鉴 dbs-script-flow）
- 终极测试：朗读。念不顺的句子全部重写

### 6. IP官
只管一件事：**跨视频的人设一致性 + 这稿像不像用户本人。**
- **语料比对**：把成稿与 P3 对话中用户的原话并排比对——成稿里出现了用户从没用过的句式、节奏、用词 = AI 代写痕迹，退回重写
- 对照 IP 定位卡：这条的语气/立场/审美和以往的成稿一致吗？
- 主契约漂移检查：这条的契约类型是否在定位卡的「主契约+可辅」清单内
- 高光挂载与库内记录一致性

### 7. 结构官
只管一件事：**骨架宏观节拍是否跑偏（整体递进落地）。**
- 对照 P4 分段骨架逐段核对：该段功能是否兑现、秒数是否匹配、结尾履约点是否送达
- 铺垫→升级→着陆必须真升级，钩子后平台期 = 违规
- 空帧检查：每 ≥4s 的段答得出「在表达什么」吗
- **不再重复前 3 秒/5s/8-20s 的逐点复查**（那是节奏官/逻辑官的活，本官只管骨架对照）

## 输出格式

```
## 七官审查报告（第 N 轮）

| 官 | 判决 | 问题定位 | 修复动作 |
|----|------|---------|---------|
| 事实 | 过/杀 | 段X句Y | 删/标待确认 |
| 节奏 | ... | ... | ... |
| 逻辑 | ... | 段X→段Y 断点描述 | 过渡句/删/重排 |

冲突裁决记录：___（哪两官冲突，按什么优先级裁的）
本轮已改：___
剩余问题+风险：___
下一步：进朗读环节 / 再审一轮（剩 N 轮）/ 交用户终审

## 朗读反馈（用户填）
念不顺的句子：段X「___」——（卡在哪/气口不对/读不下去）
```

## 与外部 skill 的配合

- dbs-script-flow 可在七官之后追加运行（其逻辑延续检查与逻辑官/口语官互补，尤其补「生造概念/术语未解释」检查项——口语官职责已并入该检查）
- dbs-ai-check 可在 IP官 环节辅助检测 AI 味——注意其立场是「只识别不改、反对伪装成人类」：本系统的用法是借它的 22 个特征做**初筛提示**，最终改稿仍以「说话指纹对齐」为准，不模板化注入停顿/改口
